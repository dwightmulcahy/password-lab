Why this score?

How the calculation works

This page separates password guessability from attack speed.

Step What happens
1. Pattern matching zxcvbn-ts searches for dictionary words, common passwords, names, dates, repeats, sequences, keyboard patterns and l33t substitutions.
2. Guess estimate It finds a low-cost attack path and returns an estimated number of guesses.
3. Entropy view This page shows log2(guesses) as “guess entropy.” It is a convenient representation of the guess count, not proof that the password was generated randomly.
4. Crack time estimated guesses ÷ guesses per second.

Important interpretation notes

Why not show just one “time to crack”?

Because there is no single attacker speed. An online login can be limited to a handful of attempts per second, while a stolen fast password hash may be attacked vastly faster offline.

Why use zxcvbn-ts?

Its core advantage is attacker-inspired pattern matching. A password such as P@ssw0rd123! should not receive full credit for every character merely because it contains upper/lowercase letters, numbers and symbols.

Does a score of 4 mean “safe”?

No. It means the estimator considers it relatively difficult to guess under its model. Reuse, phishing, malware, credential theft, weak password storage and breached secrets are separate risks.

What should a production login system do?

Use unique passwords, MFA where appropriate, breach screening, rate limiting, and a modern password-hashing configuration. OWASP currently recommends Argon2id first, with scrypt, bcrypt for legacy systems, or PBKDF2 where FIPS requirements apply.
